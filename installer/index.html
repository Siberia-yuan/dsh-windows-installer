Windows 补丁：改了什么、为什么

修改原因
.npmrc → npmmirror 镜像国内网络下 npm 官方源慢/不可达
pnpm-workspace.yaml → nodeLinker: hoistedpnpm 隔离 linker 在本项目 Windows 上顶层链接失败（typescript / @types/node / 原生预编译包缺失 → tsc TS2688）；hoisted 扁平结构避开符号链接
pnpm-workspace.yaml → verifyDepsBeforeRun: false防止 pnpm run 前自动重装，清掉手动创建的 workspace junction
allowBuilds.koffi: falsekoffi 的 cnoke 源码构建在 Git Bash（MSYSTEM）下误选 MinGW 生成器失败；改用其预编译二进制
allowBuilds.subprocess-local: false其 postinstall（macOS 专用）在 Windows 抛错会中断整个安装
根 package.json postinstall → no-oplefthook git hooks 仅开发用，且缺 Windows 二进制会致安装失败
subprocess-local package.json postinstall → no-op同上（macOS spawn-helper 修复，Windows 不需要）

安全模型速览

  • 先看后装：任何安装动作前都可运行 install-dsh.cmd --dry-run 预览。
  • 修改可核对：安装后运行 git diff 即可看到安装器对仓库的全部改动。
  • 范围受限：只写安装目录；可选的自包含 Node 下载到 installer\tools\，不装系统。
  • 可卸载：删除安装目录 + 桌面快捷方式即完成卸载，无残留。
  • 镜像可配置：GitHub 克隆与 npm registry 镜像均在脚本顶部，可自行修改。

3 步审计流程

步骤操作目的
1用记事本阅读本目录所有脚本（共 6 个文件，都很短）确认没有任何隐藏行为
2运行 install-dsh.cmd --dry-run看到实际将执行的每一步命令
3安装后运行 git diff（在安装目录）逐条核对补丁与文档描述一致

常见问题

  • clone 失败/被墙？ 安装器默认走 ghfast.top 镜像，失败自动回退直连。
  • pnpm install 失败？ 多为网络波动，重跑一次即可（安装器幂等）。
  • 构建报 TS2307？ workspace junction 未建好，重跑 node link-workspace.mjs <安装目录>。
  • 不想装 Python？ 加 --no-shortcut 跳过桌面快捷方式。
  • 如何升级？ 在安装目录运行 git pull 后重新执行安装器即可。
